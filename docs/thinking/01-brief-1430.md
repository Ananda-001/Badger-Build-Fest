# Assay: team brief (Sat Sep 26, ~14:30)

Visual version: https://claude.ai/artifact/G2cHwxerBux15srobEKnLs

## 1. The idea in one paragraph
**Assay is a proof engine for AI agents.** Agents keep being given more freedom: act without asking, run on
cheaper models, learn from corrections. Assay decides, **with evidence**, when each of those is safe:
a verdict plus an error bar, never a vibe. **We did not switch to a Jira project.** Jira ticket triage is the
*demo agent* we use to prove the engine on real data, and it runs on **Databricks**.

## 2. The three questions Assay answers
| # | Question | Verdicts | Example |
|---|---|---|---|
| 1 | **Can the agent act alone?** | auto / suggest / stay quiet | "Auto-link duplicates at confidence ≥ 0.95: precision proven ≥ 90%" |
| 2 | **Can it run cheaper?** (our original idea) | certify / reject / need N more | "Haiku instead of Sonnet: REJECTED, it costs +90% per task" |
| 3 | **Did it really learn from a correction?** | keep / discard / unproven | "New rule fixes 11, breaks 0: KEEP" |

## 3. The demo agent
For each new ticket in the **public Apache Jira** (Spark, Flink, Kafka, Hive) it decides whether the ticket is a
**duplicate** of an earlier one, **part of** an umbrella ticket (the superset idea), **related**, or **new**. Then it
links, nests or flags it. Humans accept or reject in a small review app, and every click becomes evidence for Assay.
- **Why Jira:** years of **real maintainer decisions** to check against (13,687 real links), free and without a login.
- **Why Databricks:** the Xorbix challenge asks for "an agent that reads, decides, acts and improves when a human
  corrects it". That's exactly this. Tickets go in tables, models are served by Databricks, and the app is a Databricks App.
- **Challenges** (declare by tomorrow): Applied AI track + **Databricks (Xorbix)** + **Art of the Break**.

## 4. How we got here (why it's not a pivot)
1. Agent cost control plane → 2. Assay v1–v5: certify cheaper models (simulated) → 3. overnight real Claude
experiments: real cache costs, **but every model scored 100% on clean tasks** → 4. at the event: Databricks already
does automatic model routing (but doesn't describe proving quality) → 5. **same engine, now governing a real agent on
real, messy data.**

## 5. Real results so far (no simulation)
**Overnight lab (500+ real Claude runs, $0 paid through the subscription):**
- Switching a conversation from Opus to Sonnet for one turn cost **4.1×** staying on Opus (the cache is lost).
- Subagents started in parallel **each** pay the full cold cache cost.
- A setup used only occasionally cost **2.25×** per task (small sample).
- Cost per task vs Opus: Opus-low −19%, Sonnet −38%, Haiku −70%. **All 100% accurate on clean lookups (too easy).**

**Today, on real Apache Jira (37,853 tickets since 2023):**
- 48% of tickets closed as duplicates **never link to the original**, so that knowledge is lost (the agent can recover it).
- Search (finds the true match in the top 10): duplicate **72.5%**, part-of **57.2%** (13.6% before our "sibling
  vote" fix), related 49.4%.
- Hardness test, 60 real tickets × Haiku and Sonnet: **real task, real gaps.** Duplicate and part-of precision 50–67%;
  "related" only ~8%.
- **What Assay said:**
  - "related": stay quiet
  - duplicate and part-of: no proven auto zone yet (need more evidence; the most confident duplicate calls were 86–100% right)
  - **Haiku instead of Sonnet: REJECTED.** Haiku did 1,700 hidden "thinking" tokens per call, while Sonnet did 0,
    so the "cheap" model cost 90% more per task.
- **Break Card material:** models are overconfident on "part of" (probably mistaking siblings for the umbrella), and
  the cheap model's hidden thinking makes it the expensive one.
